# Handoff acknowledgement journal, without stop authority

This increment supplies persistence and readback independently of the unresolved
authenticated ingress. It does not add a listener, credential, CLI mutation,
stdin command, process stop, task replay or an authority flag callers can enable.
The existing foreground host and lifecycle remain the only runtime.

## Implemented interface

The **internal** `StateStore.recordHandoff(payload)` returns a durable
`recorded_unverified` observation after publication. Its caller must be the
existing host/lifecycle lease owner and use that runtime's StateStore instance.
It is not reachable through public CLI, stdin, configuration or a remote API.
`markHandoffUnknown(requestId, payloadSha256)` records uncertainty without any
process action. The state is monotonic: a duplicate record never changes unknown
back to recorded. A different request cannot replace the unresolved slot.

The public, read-only command is:

```text
node <configured-endpoint-entry> host handoff-status --root <configured-hostRoot> --request-id <original-UUID>
```

It uses the existing configuration's device identity and existing
`data/endpoint/lifecycle.json`. It creates no directory, starts no runtime and
does not acquire or steal a writer lease. The established owner -> MCP -> Agenvo
-> Herdr `pane.run/read` path can execute this finite query when its original
control pane is usable. The owner must configure both entry and hostRoot;
workspace paths and labels cannot supply either. A query does not authenticate
the declarations in the record or prove the current host/native process is live.

Every result has `stop_authority:false`, `stop_dispatched_by_ack:false`,
`business_dispatched_by_ack:false`, `automatic_retry:false`, and
`principal`, `locator` set to `unverified`. `binding_evidence` is explicitly
`unverified_declaration`. These describe this acknowledgement module's effects,
not whether another actor ever stopped a process. There is no success state for
stop and no transition that enables stop. An absent/different UUID returns
`not_recorded_unknown`; absence is not permission to send another stop.

## Bound payload, version 1

All objects reject unknown/missing fields. The public synthetic
[vector](../test-support/handoff-v1.json) gives a complete payload and digest.

| Field | Meaning |
| --- | --- |
| `schema`, `request_id` | Payload version 1 and caller-retained canonical nonzero UUID. No ID is generated by the recorder. |
| `host.run_id` | Exact expected original foreground run UUID. |
| `host.root_sha256`, `program_sha256`, `configuration_sha256` | Digests of the explicit locator/program/configuration evidence; never guessed from the task workspace. |
| `native` | Exact `device_id`, `runtime_id`, `instance_id`, `session`, `herdr_pid`, `herdr_generation`, `connector_pid`, `connector_nonce`. The marker PID must agree with the supplied PID. |
| `gate` | Existing `connection_id`, `device_id`, `instance_id`, pause `request_id`, decimal-string `revision`, `paused:true`, `scope:owner_connection_instance`. Device/instance must agree with `native`. |
| `operations` | Set of original `operation_id`, decimal-string `revision`, and `reconciliation_sha256`; duplicate IDs reject. The digest binds the original owner's complete reconciliation snapshot, without copying a second task ledger here. |

These are format and identity-consistency checks, **not** verification of a
Memoh principal, native pipe peer, current admission gate, complete machine-wide
coverage or completed business. The digest conventions for the future trusted collector are:

- `root_sha256`: SHA-256 of UTF-8 `fs.realpath(hostRoot)`, with native separators
  and no case folding, trimming or Unicode normalization. The owner must retain
  that exact verified locator; it is not derived from a workspace.
- `program_sha256`: the existing candidate manifest's exact file-byte digest
  (`candidate-summary.json.manifest_sha256`), not a version label or PATH lookup.
- `configuration_sha256`: SHA-256 of compact UTF-8 JSON for the two-element array
  `[raw endpoint.json text, raw runtime.json text or null]`, preserving file bytes
  represented by those UTF-8 strings. No parsed configuration is normalized.
- `reconciliation_sha256`: SHA-256 of the exact UTF-8 reconciliation document
  retained by the original owner, not a reserialized/rounded JavaScript object.

Collection and verification of these facts still belong to the future trusted
ingress. This recorder treats them as opaque declarations. Operation snapshots
remain owned by Memoh. It cannot replace them with local receipt inference.

For request-content equality, sort operations lexicographically by operation UUID,
sort every object's keys lexicographically, serialize compact JSON as UTF-8
(no trailing newline, no HTML escaping or Unicode normalization), then SHA-256.
Decimal strings remain strings, including values above JavaScript's integer
precision. Object-key and operation ordering do not change the request digest.
Same UUID/different content gives `handoff_content_conflict`; a different UUID
while this slot is unresolved gives `handoff_request_pending`. The vector fixes
this equality rule for the consumer. It does not define an authentication token.

## Persistence, restart and compatibility

The acknowledgement is one optional field in the existing lifecycle journal,
not a new file queue or task ledger. First recording changes **only that journal**
from schema 1 to schema 2 while preserving lifecycle/continuation fields. New
readers accept old schema 1 unchanged. Earlier schema-1-only readers reject
schema 2, so rollback cannot silently drop the acknowledgement. Do not manually
downgrade or delete it. This increment provides no retirement/reset operation.

Writes on the same owner Store instance are serialized. Ordinary lifecycle saves
merge the latest persisted acknowledgement so an older in-memory state cannot
erase or regress it. The existing single-writer lease remains required; this is
not a multi-writer database CAS. Temp-file write/sync and rename use the existing
journal mechanism. The existing 256 KiB journal-read bound also bounds writes;
oversized input fails intact, never truncating an operation set. This is a control
journal bound, not a transfer quantity/file-size budget.

Write failure is `handoff_persistence_unknown`: query the original UUID. After
publication an acknowledgement may already exist even if the response failed.
Before publication the old journal remains authoritative; staging files are
retained and never adopted by a query. Process-crash tests are not power-loss or
directory-sync guarantees. Neither a timeout nor a missing response triggers
retry, stop, fresh task admission or Pi replay.

A restarted public host reports `host_handoff_unverified` and starts no components
from an unresolved record. Program switching also defers with that reason.
Existing `task_handoff_unverified`, ownership checks, transfer attention and TLS
qualification remain. Recording an observation does not clear those gates or
stop a currently running task.

## Isolated verification and remaining ingress

Tests execute real Node writer/reader/foreground processes in temporary roots,
including termination after file sync and after publication. They cover duplicate
readback, conflicting bindings, uncertainty, permission/full-disk failures,
concurrent lifecycle saves, unchanged original bytes and deferred deployment.
The host restart test injects synthetic components through the existing source
fixture and asserts zero starts/stops/business actions. It is not an authenticated
Memoh-to-Windows stop or a real Herdr/Pi handoff.

The fixed Memoh admission contract at `8d583a14f355630a5f4d71976c8265ec1575846c`
remains an owner/connection/instance pause, not a host permit. Unified ownership
code owns endpoint location and call authentication. Until that boundary is
established, no caller can promote these records to authorization; `pane.run`
acceptance is not durable completion. The only new public capability is readback.
